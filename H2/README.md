En el diagrama inicial de H1, clases como Venta y Vendedor acumulaban responsabilidades de negocio e infraestructura (persistencia directa), violando el principio SRP (Responsabilidad Única). Para corregirlo, se extrajo la orquestación del flujo comercial hacia VentaService y la gestión del catálogo a servicios dedicados. Para eliminar los new incrustados y el acoplamiento a la base de datos, aplicamos el principio DIP (Inversión de Dependencias) creando el contrato VentaRepositoryInterface, logrando que la lógica de negocio dependa de una abstracción y no de la infraestructura. Esta separación nos permitió cumplir con el principio OCP (Abierto/Cerrado), ya que ahora es posible alternar entre el almacenamiento real (MySqlVentaRepository) y repositorios en memoria (InMemoryVentaRepository) mediante inyección de dependencias sin modificar una sola línea de código del dominio.
